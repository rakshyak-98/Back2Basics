## Read and restate the problem

- Read the problem twice. Write down: **input**, **output**, **constraints** (time limit, array size, value range).
- Restate it in your own words in plain language. This catches misunderstandings early.

## Examples and edge cases

- Work through 2–3 small examples by hand. What happens step by step?
- List edge cases: empty input, min/max values, duplicates, sorted vs unsorted.

## Brute force first

- Write the simplest solution, even if it is slow.
- Note time and space complexity. You need a working baseline before optimizing.

## Improve step by step

- Find what makes brute force slow (repeated work, nested loops).
- Try known patterns: sorting, hashing, two pointers, divide and conquer, DP, greedy.
- Change one thing at a time and check with an example.

## Pseudocode

- Write logic in plain steps before code. No syntax yet.
- Walk through one example. Does each step make sense?

## Code and test

- Implement in your language.
- Test normal cases and edge cases. Fix bugs by reasoning, not guessing.
- State final time and space complexity.

## Reflection

- What pattern did you use? What similar problems use the same idea?
- What tripped you up? How will you spot it next time?
